# 캐릭터 계산기 작업 절차

목표는 캐릭터당 10분이다. 제한 시간이 아니라 측정 목표이며, 초과를 이유로 고유 규칙이나 검증을 생략하지 않는다.

## 1. 자료를 한 번에 준비

```powershell
npm run combat:prepare -- 158 --role support
```

`reports/combat-work/158-support/packet.json`에 역할별 잠재력, 실제 스킬, 원본 참조 위치와 데이터, 레벨별 값, 공통 효과 분류, 콤보 이벤트 그룹·타격 시점·무기·누락 클립을 모은다. `source.md`에는 원본을 모은다. 같은 모델을 쓰는 별도 모드의 몬스터는 직접 참조된 ID와 구분한다.

원본 위치는 `STELLA_MANAGED_SOURCE` 또는 `--source`로 지정한다. 다시 준비해도 시작 시각은 유지하며, 새 작업 측정은 `--restart`를 사용한다. 보고서는 재생성 가능한 로컬 산출물로 Git에서 제외한다.

자동 자료의 숫자 일치는 참조 **후보**다. 상수 충돌·사용하지 않는 코드가 있을 수 있으므로 실행 순서나 구현 완료로 해석하지 않는다.

## 2. 고유 규칙 구현 후 해당 캐릭터만 검사

```powershell
npm run combat:check -- 158 --role support --party 103,158,134
```

- 실제 잠재력 풀에서 기본·잠재력별·전체 잠재력의 0~5돌파 조합을 만든다. 최대 레벨 1인 잠재력은 1로 유지한다.
- 180초 계산, 동일 입력 재현, 지원 위치 교환을 검사한다.
- 해당 캐릭터의 고유 동작 테스트와 타입검사도 실행한다. 추가 관련 테스트는 `--test src/...test.ts`로 지정한다.
- 기존 전용 테스트가 같은 잠재력·돌파 조합과 재현 검사를 이미 모두 수행하면 파일에 `// combat-workflow: native-matrix`를 명시해 중복 재생을 피한다. 단순히 테스트 파일이 있다는 이유로 생략하지 않는다.
- `verification.json`에 실행 결과·소요 시간·600초 목표 초과 여부를 저장한다. 자동 조합 검사는 고유 메커니즘의 정답 검증을 대신하지 않으며, 완료를 자동 선언하지 않는다.

`--party`는 서로 다른 ID 세 개를 메인·지원1·지원2 순서로 받는다. 생략한 경우 검증용 파티를 사용하며, 사이트의 사용자 파티를 변경하지 않는다.

## 3. 묶음 작업 마지막에만 전체 검사

```powershell
npm run combat:finalize
```

타입검사 후 전체 테스트와 배포 빌드를 한 번씩 실행한다. 캐릭터를 구현하는 중간 수정마다 반복하지 않는다. 실패하면 로그를 읽고 관련 테스트로 원인을 확인한다. 커밋·푸시·배포는 하지 않는다.

자동화 자체의 검사는 `npm run combat:workflow-test`다.
