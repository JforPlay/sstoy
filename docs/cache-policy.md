# 배포 캐시와 데이터 갱신

- 캐릭터·레코드·하우징·공략 등 모든 페이지가 공통 서비스 워커 등록 코드를 사용합니다. 페이지 진입 시 브라우저 HTTP 캐시를 거치지 않고 워커 업데이트를 확인합니다.
- 번역, JSON 데이터, 고정 주소의 이미지와 모델은 네트워크 우선입니다. HTTP 캐시를 재검증하며, 오프라인이나 서버 5xx 오류에만 이전 캐시로 대체합니다. 404는 이전 파일로 숨기지 않습니다.
- 파일명에 내용 해시가 붙는 배포 JS·CSS만 캐시 우선입니다. 수정되면 파일명이 달라집니다.
- 빌드 시 GitHub 커밋 SHA(로컬 빌드는 생성 시각)를 번역·공통 JSON·하우징 모델 주소와 워커 캐시 이름에 자동 반영합니다. 데이터만 바꿔 배포해도 수동 캐시 버전 갱신은 필요하지 않습니다.
- 새 워커가 활성화되면 이전 앱 캐시를 정리합니다. 범용 이름을 쓰던 레거시 캐시는 이 사이트 경로의 항목만 지웁니다. 브라우저의 localStorage에 저장된 빌드·하우징 배치·언어·테마는 삭제하지 않습니다.
- localhost 개발 서버는 새 워커를 설치하지 않습니다. 이미 설치된 옛 워커가 있으면 업데이트하되, 새 워커는 개발 요청을 캐시하거나 가로채지 않습니다.
- 기존에 열려 있는 화면을 강제로 재시작하지 않습니다. 배포 후 워커 업데이트가 적용된 다음 일반 새로고침으로 새 코드와 데이터를 로드합니다. 실제 GitHub Pages 배포 완료·CDN 전파 시간은 별개입니다.
- 검증: `npm test`, `npm run typecheck`, `npm run build`. 캐시 회귀 테스트는 `src/shared/__tests__/service-worker.test.ts`, 주소 버전 테스트는 `asset-url.test.ts`입니다.
